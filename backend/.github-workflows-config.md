# Backend CI/CD Pipeline Configuration

## Overview

This document describes the CI/CD pipeline setup for the Spring Boot backend application.

## Workflow Files

### 1. `backend-ci.yml` - Main CI/CD Pipeline
**Triggered on:** Push to main/develop, Pull Requests
**Jobs:**
- **build**: Compiles the application using Maven
- **test**: Runs all tests and uploads results
- **code-quality**: Runs SonarQube analysis (optional)
- **security-scan**: OWASP Dependency Check for vulnerabilities
- **docker-build**: Builds and pushes Docker image (only on main/develop)
- **deploy-staging**: Deploys to staging environment (on develop)
- **deploy-production**: Deploys to production (on main)

### 2. `backend-build.yml` - Build & Test Workflow
**Triggered on:** Push to all branches, Pull Requests
**Jobs:**
- **validate**: Validates Maven configuration
- **compile**: Compiles source code
- **unit-tests**: Runs unit tests with coverage report
- **integration-tests**: Runs integration tests against MySQL
- **package**: Creates JAR artifact

### 3. `backend-lint.yml` - Code Quality Checks
**Triggered on:** Push to main/develop, Pull Requests
**Jobs:**
- **checkstyle**: Code style validation
- **spotbugs**: Bug detection
- **pmd**: Code analysis
- **dependency-check**: Security vulnerabilities

## Required GitHub Secrets

Set the following secrets in your GitHub repository settings:

### Docker Secrets (for docker-build job)
- `DOCKER_USERNAME`: Your Docker Hub username
- `DOCKER_PASSWORD`: Your Docker Hub access token

### Staging Deployment Secrets
- `STAGING_SERVER`: Staging server IP/hostname
- `STAGING_USER`: SSH user for staging server
- `STAGING_KEY`: SSH private key for staging server

### Production Deployment Secrets
- `PROD_SERVER`: Production server IP/hostname
- `PROD_USER`: SSH user for production server
- `PROD_KEY`: SSH private key for production server

### SonarQube Secrets (optional)
- `SONAR_HOST_URL`: SonarQube server URL
- `SONAR_LOGIN`: SonarQube authentication token

## How to Use

### 1. Initial Setup

1. Add the workflow files to `.github/workflows/`
2. Configure required GitHub secrets
3. Ensure your backend pom.xml includes testing dependencies:
   ```xml
   <dependency>
       <groupId>org.springframework.boot</groupId>
       <artifactId>spring-boot-starter-test</artifactId>
       <scope>test</scope>
   </dependency>
